BEACH BARBERSHOP - RÉSZLETES PROJEKT DOKUMENTÁCIÓ


1. MI AZ ALAPÖTLET ÉS CÉL?

A Beach Barbershop egy modern, felhasználóbarát webes platform, amely egy fodrászati szalon digitális jelenlétét hivatott megteremteni. A projekt fő célja, hogy egy központi felületet biztosítson, ahol az ügyfelek kényelmesen intézhetik a szalonnal kapcsolatos ügyeiket, a vezetőség pedig hatékonyan menedzselheti a napi működést.

Főbb célkitűzések:
  • Ügyfélélmény javítása: Egyszerű, gyors online foglalási és vásárlási lehetőség biztosítása.
  • Adminisztráció egyszerűsítése: Az adminisztrátorok számára egy átlátható felületet nyújtani a foglalások, rendelések és felhasználók kezelésére.
  • Modern online jelenlét: Egy esztétikus, reszponzív és megbízható weboldal létrehozása, amely vonzza és megtartja az ügyfeleket.

Az oldal lehetővé teszi az ügyfeleknek, hogy egyszerűen foglalásokat tudjanak tenni, termékeket vásároljanak meg a webshopból, saját fiókjukban kezeljék az adataikat és nyomon követhessék rendeléseiket. Az adminisztrátorok pedig teljes kontrollt kapnak a háttérfolyamatok felett.


2. FELHASZNÁLT TECHNOLÓGIÁK ÉS MIÉRT EZEKET VÁLASZTOTTUK?

A technológiai stack kiválasztásánál a megbízhatóság, a gyorsaság és a modern fejlesztési elvek voltak a fő szempontok.

Backend Technológiák:
  • Node.js: Aszinkron, eseményvezérelt futtatókörnyezet, amely kiválóan alkalmas nagy forgalmú, valós idejű webalkalmazásokhoz. A JavaScript ökoszisztéma (npm) hatalmas támogatást nyújt.
  • Express.js: Minimalista és rugalmas Node.js web framework, amely gyors API-fejlesztést tesz lehetővé anélkül, hogy felesleges absztrakciókkal terhelné a projektet.
  • Prisma ORM: Modern, típusbiztos ORM (Object-Relational Mapper), amely leegyszerűsíti az adatbázis-műveleteket. A séma definícióból generált kliens segít elkerülni a gyakori adatbázis-hibákat.
  • SQLite: Könnyű, szerver nélküli, fájl alapú adatbázis. Ideális választás kisebb és közepes projektekhez, ahol nincs szükség komplex, dedikált adatbázis-szerverre.

Frontend Technológiák:
  • HTML5: A weboldalak szabványos leíró nyelve, amely biztosítja a szemantikus és strukturált tartalmat.
  • CSS3: A modern stíluslapok nyelve, amely lehetővé teszi a reszponzív design, animációk és komplex vizuális effektek megvalósítását.
  • EJS (Embedded JavaScript): Egyszerű template engine, amely lehetővé teszi, hogy a szerver oldalon dinamikusan generáljunk HTML tartalmat adatok alapján. Tökéletes választás, ha nincs szükség egy teljes frontend framework (pl. React, Vue) komplexitására.
  • Vanilla JavaScript: A böngészőben futó, keretrendszer nélküli JavaScript. Ezzel az interaktív funkciók (pl. modal ablakok, űrlap validáció, API hívások) gyorsak és pehelysúlyúak maradnak, minimalizálva a betöltési időt.



3. ADATBÁZIS-STRUKTÚRA

Az alkalmazás adatmodellje a `schema.prisma` fájlban van definiálva. Három fő entitás köré épül, amelyek relációban állnak egymással.

USER (Felhasználók) - A rendszer felhasználóit tárolja.
  • id: Int - Egyedi, auto-inkrementált azonosító (Primary Key).
  • felhnev: String - A felhasználó által választott, egyedi felhasználónév.
  • email: String - Egyedi email cím, amelyet a bejelentkezéshez használunk.
  • password: String - A jelszó biztonságosan tárolt, bcrypt algoritmussal titkosított hash-e.
  • telefonszam: String? - Opcionális telefonszám.
  • pnumber: String? - Opcionális második telefonszám.
  • role: String - A felhasználó szerepköre (USER, BARBER, ADMIN), amely a jogosultságokat határozza meg.
  • createdAt: DateTime - A regisztráció pontos időpontja.
  • bookings: Booking[] - Reláció: egy felhasználónak több foglalása is lehet.
  • orders: Order[] - Reláció: egy felhasználónak több rendelése is lehet.

BOOKING (Foglalások) - Az időpontfoglalásokat rögzíti.
  • id: Int - Egyedi, auto-inkrementált azonosító (Primary Key).
  • datetime: DateTime - A foglalás pontos időpontja.
  • service: String - A kiválasztott szolgáltatás neve (pl. "Hajvágás", "Szakálligazítás").
  • userId: Int - A foglalást végző felhasználó azonosítója (Foreign Key).
  • user: User - Relációs hivatkozás a `User` táblára a `userId` alapján.

ORDER (Rendelések) - A webshopban leadott rendeléseket tárolja.
  • id: Int - Egyedi, auto-inkrementált azonosító (Primary Key).
  • products: String - A rendelt termékek listája JSON formátumban, amely tartalmazza a termék nevét, mennyiségét és árát.
  • totalPrice: Int - A rendelés teljes végösszege.
  • shippingType: String - A szállítás típusa (pl. "home" - házhozszállítás, "pickup" - személyes átvétel).
  • createdAt: DateTime - A rendelés leadásának pontos időpontja.
  • userId: Int - A rendelést leadó felhasználó azonosítója (Foreign Key).
  • user: User - Relációs hivatkozás a `User` táblára a `userId` alapján.



4. API VÉGPONTOK RÉSZLETESEN

Az alkalmazás egy RESTful API-t használ a kliens (böngésző) és a szerver közötti kommunikációra. A végpontok a `src/index.js` fájlban vannak definiálva.

Autentikációs végpontok:
  • POST /api/register: Új felhasználó regisztrálása. A request body-ban várja a `felhnev`, `email` és `password` mezőket. Sikeres regisztráció után a felhasználó a bejelentkezési oldalra kerül.
  • POST /api/login: Felhasználó bejelentkeztetése. A request body-ban `email`-t és `password`-öt vár. Sikeres bejelentkezés esetén egy session jön létre, és a felhasználó a szerepkörének megfelelő oldalra (fiók vagy admin panel) lesz irányítva.
  • GET /api/logout: Kijelentkezteti a felhasználót, megszünteti a session-t, és a főoldalra irányít.

Felhasználói (USER szerepkör) végpontok:
  • GET /api/bookings: Visszaadja a bejelentkezett felhasználó összes foglalását.
  • POST /api/booking: Új foglalás létrehozása. A request body-ban `datetime`-ot és `service`-t vár.
  • DELETE /api/booking/:id: Törli a megadott azonosítójú foglalást, de csak akkor, ha az a bejelentkezett felhasználóhoz tartozik.
  • GET /api/orders: Visszaadja a bejelentkezett felhasználó összes rendelését.
  • POST /api/order: Új rendelés létrehozása. A request body-ban a `products`, `totalPrice` és `shippingType` adatokat várja.

Adminisztrátori (ADMIN szerepkör) végpontok:
  Ezek a végpontok egy middleware által védettek, amely ellenőrzi, hogy a bejelentkezett felhasználó rendelkezik-e 'ADMIN' szerepkörrel.
  • GET /api/admin/bookings: Visszaadja az összes foglalást a rendszerben.
  • GET /api/admin/orders: Visszaadja az összes rendelést.
  • DELETE /api/admin/order/:id: Törli a megadott azonosítójú rendelést.
  • GET /api/admin/users: Visszaadja az összes felhasználót.
  • POST /api/admin/user/:id/update: Módosítja egy adott felhasználó adatait (`felhnev`, `email`, `telefonszam`, `pnumber`, `role`).
  • POST /api/admin/user/:id/password: Módosítja egy adott felhasználó jelszavát.
  • DELETE /api/admin/user/:id: Törli a megadott azonosítójú felhasználót.



5. FŐBB FUNKCIÓK ÉS MŰKÖDÉSÜK

Az alkalmazás funkciói szorosan kapcsolódnak egymáshoz, hogy egy teljes körű élményt nyújtsanak.

Autentikáció és Felhasználó Kezelés:
  • Regisztráció: A felhasználók egy egyszerű űrlapon regisztrálhatnak. A szerver validálja az adatokat (pl. email formátum, jelszó erőssége), és a jelszót a `bcrypt` könyvtár segítségével hash-eli, mielőtt az adatbázisba mentené.
  • Bejelentkezés: A bejelentkezés során a rendszer összehasonlítja a megadott jelszó hash-ét az adatbázisban tároltal. Sikeres azonosítás után egy session jön létre a felhasználó azonosítójával és szerepkörével, amelyet egy cookie-ban tárol a böngésző.
  • Jogosultságkezelés: A szerveroldali middleware minden védett kérésnél ellenőrzi a session-ben tárolt szerepkört, így biztosítva, hogy pl. admin funkciókat csak adminisztrátorok érhessenek el.

Foglalási Rendszer:
  • Időpont és szolgáltatás választása: A felhasználók egy interaktív felületen választhatnak a rendelkezésre álló időpontok és szolgáltatások közül.
  • Foglalás rögzítése: A kiválasztott adatokkal a kliens egy POST kérést küld a `/api/booking` végpontra. A szerver a bejelentkezett felhasználóhoz köti a foglalást.
  • Foglalások megtekintése és törlése: A "Fiók" oldalon a felhasználók listázhatják a jövőbeli foglalásaikat, és egy megerősítő modal ablak után törölhetik azokat.

WebShop:
  • Termékek böngészése: A termékek dinamikusan jelennek meg a "Shop" oldalon. Lehetőség van kategóriák szerinti szűrésre.
  • Kosár kezelése: A kosár tartalma a böngésző `localStorage`-ében tárolódik. Ez lehetővé teszi, hogy a kosár tartalma megmaradjon az oldal újratöltése vagy a böngésző bezárása után is. A termékek mennyiségét egy modal ablakban lehet módosítani.
  • Fizetés: A "Fizetés" gombra kattintva a felhasználó egy összegző oldalra jut, ahol áttekintheti a rendelését, és megadhatja a szállítási adatokat. A rendelés leadásakor a kosár tartalma elküldésre kerül a szervernek, amely rögzíti az `Order` táblában.

Admin Panel:
  • Központi menedzsment: Az adminisztrátorok egyetlen, jól strukturált felületen kezelhetik a foglalásokat, rendeléseket és felhasználókat.
  • Interaktív táblázatok: Az adatok táblázatos formában jelennek meg, ahol lehetőség van szűrésre és keresésre.
  • Modal alapú műveletek: A törlési és szerkesztési műveletek nem egy új oldalon, hanem felugró modal ablakokban történnek, ami gyorsabbá és felhasználóbarátabbá teszi a kezelést. A felhasználók szerkesztésénél egyetlen modalban módosíthatók az adatok, cserélhető a jelszó, vagy akár törölhető is a felhasználó.
  • Visszajelzések: Minden admin művelet (sikeres vagy sikertelen) után egy "toast" értesítés jelenik meg a képernyő sarkában, egyértelmű visszajelzést adva a művelet eredményéről.

Felhasználói Élmény
  • Videó háttér az oldalak hátterében
  • Teljes responsive design (mobil, tablet, asztali)
  • Sima animációk és átmenetek
  • Zöld toast üzenet sikeres műveleteknél
  • Piros toast üzenet hibáknál
  • Modern glass morphism effect az oldalsávban



6. PROJEKT STRUKTÚRA ÉS FÁJLOK SZEREPE

A projekt könyvtárszerkezete logikusan van felépítve, hogy a különböző funkciókhoz tartozó fájlok könnyen megtalálhatók legyenek.

`src/` - A fő alkalmazás forráskódja.
  • `index.js`: A projekt szíve. Ez a fájl indítja el az Express szervert, beállítja a middleware-eket (pl. session kezelés, statikus fájlok kiszolgálása), és itt vannak definiálva az összes API végpont és a hozzájuk tartozó logika.
  • `public/`: A böngésző által közvetlenül elérhető statikus fájlok mappája.
    - `css/`: Az összes CSS stíluslap itt található, oldalanként külön fájlokba szervezve (pl. `fiok.css`, `shop.css`), ami megkönnyíti a karbantartást.
    - `js/`: Kliensoldali JavaScript fájlok. Jelenleg a `mobileNav.js` felel a reszponzív mobil menü működéséért.
    - `videos/`: Az oldalak hátterében használt videófájlok helye.
  • `views/`: Az EJS template fájlok mappája. Ezek a fájlok tartalmazzák az oldalak HTML vázát, amelyeket a szerver dinamikusan tölt fel adatokkal.
    - `index.ejs`, `bejelentkezes.ejs`, stb.: Minden egyes oldalnak saját EJS fájlja van.
    - `fiok.ejs`: Ez egy különlegesen komplex template, mert ez rendereli a normál felhasználói fiókot és az admin panelt is, a felhasználó szerepkörétől függően.
  • `generated/`: Ezt a mappát a Prisma ORM kezeli. Tartalmazza a generált Prisma klienst, amelyen keresztül az alkalmazás kommunikál az adatbázissal. Ezt a mappát manuálisan nem szabad módosítani.

`scripts/` - Segédszkriptek a fejlesztéshez.
  • `createAdminInteractive.mjs`: Egy parancssori szkript, amely interaktív módon (kérdéseket feltéve) teszi lehetővé egy adminisztrátori jogosultságú felhasználó létrehozását.

Gyökérkönyvtár:
  • `package.json`: A Node.js projekt leírófájlja. Tartalmazza a projekt metaadatait, a függőségeket (`dependencies`), és a futtatható szkripteket (`scripts`, pl. `npm start`).
  • `schema.prisma`: A Prisma ORM sémadefiníciós fájlja. Itt van leírva az adatbázis modellje (táblák, oszlopok, relációk). A `npx prisma migrate` parancs ez alapján hozza létre és módosítja az adatbázist.
  • `DOKUMENTACIO.txt`: Ez a dokumentációs fájl.
  • `Beachbarbershop.sql`: Az adatbázis séma SQL exportja, amely referencia vagy manuális adatbázis-létrehozás céljából hasznos lehet.


7. TELEPÍTÉS ÉS HELYI FEJLESZTÉSI KÖRNYEZET BEÁLLÍTÁSA

Az alábbi lépésekkel hozható működőképes állapotba a projekt egy új fejlesztői gépen.

Előfeltételek:
  • Node.js és npm telepítve kell, hogy legyen.

Lépések:

1. Projekt letöltése és függőségek telepítése:
   Klónozd a projektet, majd a gyökérkönyvtárban add ki a következő parancsot a `package.json`-ban definiált összes függőség telepítéséhez:
   ```
   npm install
   ```

2. Adatbázis inicializálása és migrálása:
   A Prisma segítségével létre kell hozni az SQLite adatbázisfájlt és futtatni kell a migrációt, amely felépíti a táblákat a `schema.prisma` alapján.
   ```
   npx prisma migrate dev
   ```
   Ez a parancs létrehozza a `prisma/dev.db` fájlt.

3. Első admin felhasználó létrehozása:
   Az admin panel eléréséhez szükség van egy adminisztrátori fiókra. A mellékelt interaktív szkript végigvezet a létrehozás folyamatán.
   ```
   node scripts/createAdminInteractive.mjs
   ```

4. Fejlesztői szerver indítása:
   Az `npm start` parancs elindítja a szervert (a `package.json` `scripts` szekciója alapján a `node src/index.js` parancsot futtatja).
   ```
   npm start
   ```

5. Alkalmazás megnyitása a böngészőben:
   A szerver alapértelmezetten a 3000-es porton indul. Nyisd meg a böngészőben az alábbi címet:
   http://localhost:3000


8. BIZTONSÁGI MEGFONTOLÁSOK

Az alkalmazás fejlesztése során több ponton is figyelembe lettek véve a biztonsági szempontok:

  • Jelszókezelés: A jelszavak soha nincsenek nyers formában tárolva. A `bcrypt` könyvtár segítségével minden jelszó "sózással" (salting) és hash-eléssel kerül az adatbázisba, ami megnehezíti a feltörésüket még az adatbázis kompromittálódása esetén is.
  • Session menedzsment: A bejelentkezett felhasználók állapotát a szerveroldali session-ök kezelik. A kliensoldalon csak egy session ID tárolódik egy `httpOnly` cookie-ban, ami megakadályozza, hogy a kliensoldali szkriptek (pl. XSS támadás esetén) hozzáférjenek.
  • Jogosultság-ellenőrzés (Authorization): Az adminisztrátori végpontok egy szerveroldali middleware-rel vannak védve, amely minden kérésnél ellenőrzi, hogy a felhasználó rendelkezik-e a megfelelő (`ADMIN`) szerepkörrel. Ez megakadályozza, hogy illetéktelenek hozzáférjenek a menedzsment funkciókhoz.
  • Input validáció: A szerveroldal minden bejövő adatot validál (pl. űrlapok, API kérések), mielőtt feldolgozná azokat. Ez védelmet nyújt a gyakori támadási formák, mint például az SQL injection vagy a Cross-Site Scripting (XSS) ellen.
  • CORS (Cross-Origin Resource Sharing): A `cors` middleware be van állítva, hogy csak a megbízható forrásokból érkező kéréseket fogadja el, csökkentve a CSRF (Cross-Site Request Forgery) támadások kockázatát.


9. DESIGN FILOZÓFIA ÉS FELHASZNÁLÓI ÉLMÉNY (UI/UX)

A design célja egy modern, letisztult és intuitív felület létrehozása volt, amely kellemes élményt nyújt a felhasználóknak.

Vizuális elemek:
  • Videó háttér: A főoldalon és más aloldalakon található finom videó háttér dinamikus és prémium érzetet kölcsönöz az oldalnak.
  • Glassmorphism: Az admin panel oldalsávján alkalmazott "üvegszerű" effekt (áttetszőség és háttér-elmosás) modern és elegáns megjelenést biztosít.
  • Színpaletta: A türkiz és a sötét színek kombinációja egyszerre professzionális és barátságos. A megerősítő (zöld) és hiba (piros) színek egyértelmű vizuális visszajelzést adnak.

Interakciók és felhasználói élmény:
  • Modal dialógusok: A kritikus műveletek (pl. törlés) és a komplexebb feladatok (pl. felhasználó szerkesztése) felugró modal ablakokban történnek. Ez a megoldás ahelyett, hogy új oldalra navigálna, a felhasználót a kontextusban tartja, és gördülékenyebbé teszi a munkafolyamatot.
  • Toast értesítések: A műveletek után megjelenő, pár másodperc után automatikusan eltűnő "toast" üzenetek diszkrét, mégis egyértelmű visszajelzést adnak a felhasználónak anélkül, hogy megzavarnák a böngészést.
  • Reszponzivitás: Az oldal teljes mértékben reszponzív. A CSS media query-k segítségével a layout automatikusan alkalmazkodik a különböző képernyőméretekhez, legyen szó mobiltelefonról, tabletről vagy asztali számítógépről. A mobil nézetben egy hamburger menü biztosítja a könnyű navigációt.
  • Sima animációk: A CSS tranzíciók és animációk (pl. gombokon, menüelemeken) finomabbá és élvezetesebbé teszik az oldal használatát.


10. FEJLESZTÉSI ÉS KARBANTARTÁSI ÚTMUTATÓ

  • API bővítése: Új API végpontokat a `src/index.js` fájlba kell felvenni. Érdemes követni a meglévő struktúrát (pl. jogosultságkezelő middleware használata).
  • Stílusok módosítása: Az oldalak kinézetét a `src/public/css` mappában található CSS fájlok módosításával lehet megváltoztatni. A BEM (Block, Element, Modifier) metodológia vagy hasonló elnevezési konvenció követése javasolt a karbantarthatóság érdekében.
  • Oldalak tartalmának módosítása: Az oldalak HTML szerkezetét és dinamikus tartalmát a `src/views` mappában lévő EJS fájlokban lehet szerkeszteni.
  • Adatbázis-séma módosítása: Ha új mezőre vagy táblára van szükség, a `schema.prisma` fájlt kell módosítani. Ezt követően futtatni kell a `npx prisma migrate dev --name <migracio_neve>` parancsot a változtatások adatbázisban való érvényesítéséhez.
  • Függőségek frissítése: A projekt függőségeit időnként érdemes frissíteni a `npm update` paranccsal a biztonsági rések és hibák javítása érdekében.


11. TESZTELÉS ÉS MINŐSÉGBIZTOSÍTÁS

A projekt végpontjainak és felhasználói felületének automatizált tesztelésére a Playwright keretrendszer van beállítva. A tesztek célja, hogy ellenőrizzék az alapvető felhasználói folyamatokat (navigáció, foglalás, bejelentkezés, webshop használata), és időben jelezzék, ha egy módosítás váratlan hibát okoz.

Használt eszközök:
  • Playwright (@playwright/test): End-to-end (E2E) böngészőtesztek írására szolgál. A Chromium alapú böngészőt használja, és valós felhasználói interakciókat (kattintás, űrlapkitöltés, navigáció) szimulál.
  • Playwright HTML riport: A tesztek lefutása után részletes, böngészőben megnyitható riportot készít a sikerekről és hibákról.

Tesztstruktúra:
  • Tesztek helye: A tesztfájlok a `tests/` mappában találhatók (pl. `homepage.spec.js`, `foglalas.spec.js`, `hitelesites.spec.js`, `navigacio.spec.js`, `shop.spec.js`).
  • Konfiguráció: A Playwright beállításai a `playwright.config.js` fájlban vannak definiálva.
    - `testDir: "./tests"`: Meghatározza, hogy honnan töltse be a tesztfájlokat.
    - `baseURL: "http://localhost:3000"`: A tesztek relatív útvonalakkal (`/`, `/foglalas`, `/shop` stb.) hivatkoznak az oldalra.
    - `webServer`: A konfiguráció a tesztek futtatása előtt automatikusan elindítja a szervert a `node src/index.js` paranccsal, és megvárja, amíg az elérhetővé válik a `http://localhost:3000` címen.
    - `workers: 1`: A tesztek egy szálon futnak, így elkerülhetőek a párhuzamos futásból adódó ütközések az adatbázisban.
    - `trace`, `screenshot`, `video`: Hibák esetén nyomkövetési fájl, képernyőkép és videó készül a hiba könnyebb visszakövethetősége érdekében.

Példák lefedett esetekre:
  • Főoldal (homepage.spec.js):
    - Ellenőrzi, hogy az oldal HTTP 200-as státuszkóddal tölt be.
    - A cím (title) tartalmazza a Beach Barbershop nevet.
    - A logó és a fő navigációs elemek (Foglalás, Webshop, Bejelentkezés) megjelennek és megfelelő oldalakra navigálnak.
  • Navigációs és funkcionális tesztek (foglalas, shop, hitelesites):
    - Tipikus felhasználói útvonalakat járnak be (időpontfoglalás, kosárkezelés, be- és kijelentkezés), és ellenőrzik, hogy a rendszer a várt URL-re navigál, illetve a várt elemek jelennek meg.

Tesztfuttatás parancsai:
  • Összes teszt futtatása (CI jellegű, fej nélküli mód):
    ```
    npm test
    ```
    Ez a `package.json` `test` scriptjét hívja meg, amely a `playwright test` parancsot futtatja.

  • Tesztek futtatása UI felülettel (Playwright Test Runner GUI):
    ```
    npm run test:ui
    ```
    Ez a parancs megnyit egy grafikus felületet, ahol egyenként indíthatók a tesztek, és valós időben látható az eredmény.

  • HTML riport megnyitása egy korábban lefutott tesztcsomaghoz:
    ```
    npm run test:report
    ```
    A riport alapértelmezetten a `playwright-report/` mappában generálódik, és böngészőben tekinthető meg.

Előfeltételek teszteléshez:
  • A projekt függőségei telepítve vannak (`npm install`).
  • A Prisma adatbázis migrációk lefutottak, és létezik az adatbázis (`npx prisma migrate dev`).
  • (Ajánlott) Legalább egy admin felhasználó létrehozása a tesztekhez és manuális ellenőrzéshez (`node scripts/createAdminInteractive.mjs`).

Ajánlott tesztelési folyamat fejlesztés közben:
  • Funkció fejlesztése → manuális ellenőrzés a böngészőben.
  • Új felhasználói folyamat esetén új Playwright teszt hozzáadása a `tests/` mappában, a meglévő specifikációk mintájára.
  • `npm test` futtatása lokálisan push előtt, hogy elkerülhetőek legyenek a regressziók.
